# Colormeris: notes for Claude sessions

Colormeris is a static web app (Landry lab, UC Berkeley) that turns colors in scientific figures back into numbers. It has two pages: `extract.html` with three tools, **heatmap** (one value per grid cell), **ROI** (signal inside regions of interest, e.g. on IVIS luminescence images) and **map** (near-continuous fields such as spectroscopy maps and fluorescence images, as a value matrix with axes and line profiles), and `colormaps.html`, a colormap viewer. `index.html` is the landing page. It also has an **agent layer**: a typed API plus an LLM agent that calibrates heatmaps by itself, in two modes: *Agent only* and *Agent decision* (the LLM asks a decision model, Jev, and the app snaps and counts). Start with [README.md](README.md) for users and [docs/agent.md](docs/agent.md) for the agent. [docs/research.md](docs/research.md) has the literature, novelty and experiment plan.

## Commands

```bash
npm run dev       # Vite dev server → http://localhost:8000/extract.html#heatmap (hot reload)
npm run check     # biome lint + tsc + vitest (must pass before commits)
npm test          # vitest only (unit tests next to their modules: src/**/*.test.ts)
npm run build     # production build in dist/; npm run preview serves it
npm run format    # biome format
npm run proxy     # OpenRouter proxy on :8787 that adds the key from .env
npm run perf      # after npm run build: timings in headless Chrome (PERF_OUT=<dir> for another build, e.g. main)
uv run --with matplotlib --with cmasher --with cmcrameri --with cmocean --with colorcet --with seaborn --with colormaps python scripts/export-mpl-colormaps.py   # regenerate src/generated/colormap-data.json
npm run docs      # regenerate docs/agent.md (a test fails if it is stale)
npm run fixtures  # regenerate src/testing/fixtures/calibration (synthetic heatmaps with known truth)
```

`.claude/launch.json` has the preview configs `colormeris` (Vite, port 8000), `colormeris-alt` (Vite, port 8002, when 8000 is taken), `colormeris-build` (build + `vite preview` on 8004) and `openrouter-proxy` (port 8787). Start them with preview_start, not Bash. CI (`.github/workflows/ci.yml`) runs lint, typecheck, tests and build on every push; `pages.yml` deploys `dist/` to GitHub Pages after CI passes on `main`.

## Secrets: read first

- The user's OpenRouter key is in `.env` as `OPENROUTER_API_KEY`. `.env` and `.env.*` are git-ignored, and the key has never been committed.
- Never print, `cat` or echo `.env`. To see which variables it has, use `sed -E 's/=.*/=<redacted>/' .env`.
- Never type the key into the browser, a URL or a tool call. For real agent runs, start the `openrouter-proxy` preview and set the Agent card's *API base URL* to `http://localhost:8787/api/v1`, leaving the key field empty. The proxy (`scripts/openrouter-proxy.mjs`) adds the key itself and forwards only `/api/v1/` and `/api/alpha/decisions`. It refuses non-localhost Origins, `Origin: null` (sandboxed iframes) and non-localhost Host headers (DNS rebinding).
- Before every commit: `git diff --cached | grep -E "sk-or-[A-Za-z0-9]{20,}"` must print nothing.
- Real runs cost the user money: about $0.2–0.8 per page with Claude Sonnet 5.5. Use small `Max. steps` and a single page.

## Architecture

TypeScript (strict) ES modules, bundled by Vite. `extract.html` and `colormaps.html` each load one entry, `src/pages/extract.ts` / `src/pages/colormaps.ts`; files import what they use (no global namespace, no load order). Typing conventions are in [docs/typescript.md](docs/typescript.md): shared domain types live in `src/types/` (`Project`, `Panel`, `Grid`, `Colorbar`, results, `Settings`, `Workspace` / `WorkspaceContext` / `ToolHooks`, agent and colormap types), no `any` (`noExplicitAny` is an error; the few casts the types can't express yet are marked `// TODO(types)`). In dev builds `globalThis.Colormeris` holds the pure modules' exports for console debugging (`Colormeris.extractPanel`); production builds don't have it. `window.colormeris` (the agent API) exists in both.

Files are grouped by feature. **Pure** files (no DOM) have unit tests next to them (`grid.ts` + `grid.test.ts`, helpers in `src/testing/helpers.ts`). Every file starts with a comment saying what it does. UI files are named for what they render: `*-tool.ts`, `*-tab.tsx`, `*-card.tsx`. The cards, the Agent card, Settings and the colormaps page are React 19 components; the viewer, overlays, results tables, plots and strips stay imperative behind refs. **Read [docs/react.md](docs/react.md) before touching UI code** (the store bridge, `src/ui/` components, the card pattern, the colormaps app, the performance budget). Shared context objects are typed: the workspace's private `w` (`WorkspaceContext`; each `workspace/*.ts` module takes it and returns its members), `RoiToolContext` (roi-tool.ts), `MapToolContext` (map-tool.ts).

### Agent design decisions (and why)

- **Coordinates** are always page pixels of the rendered page image. The LLM gets images of regions with rulers on the **bottom and right**, so image pixel (0, 0) is the region's top-left corner, and each note states `page = x0 + image / scale`. Rulers on the left and top shifted every placement by the ruler width divided by the zoom; this was measured as (+18, +8) px at 2.56×.
- **No reviewer** (removed 2026-10-05): the agent checks its own work with the calibration and reconstruction overlays and ends with `finish`. The typed questions (`get_questions`: `confirm_grid_size`, `classify_flagged`, `classify_flagged_cells`, `confirm_tick_order`, `confirm_extraction`) and `answer_question` stay in the API for external agents and people. `policy.minConfidence` (0.9) gates applying; lower answers are "escalated" to *Needs review*. `source: "human"` always applies. Earlier a smaller vision LLM (Haiku 4.5, then Jev) answered them; see docs/research.md.
- **Prompt caching**: every request sends top-level `cacheControl: {type: 'ephemeral', ttl: '1h'}` and a per-run `sessionId` (sticky routing), see the OpenRouter prompt-caching guide. `pruneImages` trims old images in steps of 4 so the request prefix stays byte-identical between steps (trimming one per step would break the cache each time). The card shows the cached share of prompt tokens (`usage.cachedTokens`). Not yet measured on a real run.
- **Reviews** (`panel.review`) are stored with the `resultHash` of the values they judged. They are `stale` once the values change; rejected panels get a red dot and Redo / Accept anyway in *Needs review*.
- **Forgiving arguments**: `normalizeArgs` drops `null` optionals, and `add_tick` with both `at` and `t` uses `at`. Models did send both, which caused endless "give exactly one of t or at" loops.
- **Snapping**: `set_colorbar` and `add_tick` (agent API only, `snap: false` to skip) move the LLM's rough points onto the colored strip and the tick marks (`refineColorbar`, `snapTick` in `core/colorbar.ts`). Measured on `example.pdf` page 5, Fig h: ends and ticks within 1 px. Ticks keep their page positions when the colorbar moves.
- **Finish check**: `finishCheck` refuses `finish` for unseen pages or half-done panels and gives a per-page checklist once; after 3 refusals any finish is accepted.
- **Retry guard**: 3 attempts per tool per panel, then blocked;  the run stops after 8 failures in a row.
- **Agent decision mode** (toggle at the top right of the Agent card, `agent.mode`): the LLM lists the heatmaps and reads text; Jev (`typesafe/jev-1.14`) answers one heatmap per request; code snaps, counts and picks. Measured on example.pdf page 5: Jev box edges have two decimals (~20 px on a page, ~5 px on a crop), Jev could not box tick-label text, counted cells badly and judged correct reconstructions as wrong, so none of those are asked. Design after diagnosing 18 real test figures (`test-images/test-1..18.png`, 2026-10-17). Jev's two requests per heatmap are sent for all `locate_heatmap` calls of a turn at once (`prefetch`; they only read the page image), the rest of each call runs in order; `makeDecisionClient` retries once on a 5xx or network error:
  - **Cells**: Jev's page box, then its crop box, each through `snapBlock` (edges at a frame's middle; a crop snap that holds the page-wide one and is >1.5× Jev's page box took in a neighbour, so the page-wide one wins). A gap of page with a frame line on both sides splits the ink core, and the part under the box's middle wins (test-1: a framed block and its framed Average row 11 px below became one 4-row block), unless every gap splits alike (each cell in its own frame, test-18). Growth crosses white gaps as wide as 6% of the box (not only of the core) and takes pale cells one pitch at a time when the block's cells repeat evenly (`pitchOf`/`paleCell`; test-16's near-white diverging cells, test-18's framed pale columns); span coverage ignores the gaps between cells. A snap that lost >15% of Jev's crop box or moved an edge >8% inward is checked against `snapEdges(crop box)`, which wins only with ≥3 edges found on pixels, a clearly better even-grid fit and whole cells added (a safety net; t10's labels 12 px past the cells once won without the last rule). With the LLM's own `box` (only after Jev found the wrong heatmap) Jev is not asked and `snapEdges` moves each edge ≤ 3%, except an edge inside the cells, which goes out to `snapBlock`'s edge (test-1: the LLM read Average rows 12 px short). Two panels on the same cells get a note (Jev boxed test-10's strip as the block under it).
  - **Counts** (`planGrid` → `planCounts`): a `fitCellCounts` score ≥ 0.7 is taken silently; else a panel on the page with the same x (or y) extent lends its count (`gridNeighbours`; test-10's gradient strip has the 28 columns of the heatmap under it), and `regridOthers` gives a later panel's count to an earlier one that was unsure; else an axis about one cell long (vs. the other axis' fit, a lined-up panel's cells or any panel's) or a strip 12× longer than thick is 1; else a fair fit (0.45–0.7) with a note only when `detectGridSize` disagrees or the next count fits nearly as well (notes on correct counts in test-2/3/6); below that `detectGridSize` with confidence ≥ 2, else the LLM counts from labels (`correct_grid_size`). Dark text printed in cells is painted over before both counters (`suppressText`: short dark dips darker than both sides; columns dark on ≥75% of lines are grid lines and stay; test-18's values gave 10 rows for 5, test-15's 21 for 7 on loose boxes). A white end cell left out ties with the count that keeps it; a lined-up panel, else `detectGridSize`, that counts it settles it and the box stays whole (test-17 panel i). A clean fit whose `span` sits inside the box moves the corners onto the counted cells; a white end row left out comes back when the LLM gives its count to `correct_grid_size`. **The LLM never sets rows or columns except through `correct_grid_size`** (rows, cols, reason, optional `box` snapped with `snapEdges`; user decision 2026-10-16).
  - **Colorbar** (`chooseColorbar`): candidates are `pageColorbars` (`findColorbars` without categorical strips, other panels' cells excluded, ≥2 tick labels) plus Jev's colorbar box through `snapStrip` when no strip is right beside the cells; every strip needs page past its ends and sides (`flankInk`: runs of cells in heatmaps not located yet passed as binned bars). `findColorbars` drops dashed lines (<90% off the page along the middle in ≥3 gaps: test-16's outline) and joins pieces of one bar split at a near-white middle (`mergeFragments`); a strip whose labels are the heatmap's own column or row labels (one per column, on its middle) is left out (`cellLabels`). `stripKind` calls a strip categorical when one color comes back in ≥3 stretches with another color between (test-13's yellow "Tails" label boxes, test-9's "Group" strip). One strip beside the cells (`besideCheck`, labels on the far side) wins; else one near (`nearCheck`); else the only one on the page (test-1). A strip exactly as long as the cells without two tick labels is never taken by itself, nor an unlabelled strip while a labelled one exists (Jev once boxed a heatmap row as the bar). Otherwise the LLM gets them lettered (numbered strips first) and calls `use_colorbar {candidate}`, `{fromPanel}` (copies bar, ticks and scale) or `{box}` (`snapStripBox`: the rest of the box is snapped too and pieces joined; under 70% of the box's length the strip is extended to it, with a warning).
  - **Ticks**: `findTickLabels` drops long thin frame pieces (test-4), stacked glyphs of a rotated title (≥3 chars a few px apart along a vertical bar; a side whose labels span < 50% of the bar scores half: test-14), joins no label taller than 1.7 glyphs (test-10's "−1 / −1.5" through a title), drops the one label on a binned bar that is off the bin steps and out of step with the rest (t2/t3 "RLU" title), flags odd-sized boxes (`note`), and extends a strip to an in-step label just past a pale end (`bar`; test-10's "1"). Without tick marks the first and last labels mark the strip's ends when they sit within half their size and a tenth of the label spacing of them (user decision 2026-10-17; test-16), else their text middles. The locate result says how many boxes exist (`tickBoxesText`). `set_ticks` takes `{mark, value}` or `{t, value}` (both snap to a tick mark within 4% of the bar); with no scale given, `scaleForBins` (binned) or `scaleForTicks` (smooth: piecewise for evenly stepped values at uneven places, test-6) picks one and says so. Its result has an image of the tick dots with their values (640 px). `set_colorbar_scale` returns the check too.
  - **Check** (`checkSummary`, from `extractPanel`'s `counts`): fails on ticks off the scale's line (`tickMisfit`, none for piecewise), >20% flagged or >30% off-map cells; off-map cells (ND gray, black diagonal: value NaN) and binned bars are expected and only reported; a clamped share >20% warns that those cells are bounds. `check_printed {cells: [{row, col, value}]}` (user decision 2026-10-17): numbers printed in cells are a cross-check, the colors stay the values; the prompt asks for 3–5 spread-out ones; `printedCheck` agrees within 3% of the tick range and names a slope or a common offset (wrong ticks or ends) or single cells off. User decisions 2026-10-17: only numerical heatmaps with a colorbar; annotation strips with their own colorbar are panels; off-map cells stay empty with a note; binned bars give bin middles.
  - Tool results carry `panelBrief` instead of the full panel (label lists cost 1.2k tokens per call). The LLM's image of a heatmap is cropped at white gaps (`labelReach`): a crop reaching into panel f made the LLM give g f's tick values.
- **Docs**: `docs/agent.md` is generated from the schemas, prompt and limits by `scripts/agent-docs.mjs`. After changing any action, prompt or limit, run `npm run docs`.

## Conventions

- Match the surrounding code: small functions, comments that explain *why*, and the existing naming. README and docs use short, plain sentences.
- Commit only when the user says "commit". Messages have a short title and a body explaining why, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. The branch is `main`; nothing has been pushed by Claude.
- Vite hashes built file names, so there is no manual cache busting. Lint and format with Biome (`biome.jsonc` says why each relaxed rule is off); formatting-only changes go in their own commit.
- Add a unit test for pure logic (`x.test.ts` next to `x.ts`: Vitest with `node:assert/strict`); browser behaviour is checked in the preview.

### UI standard (`extract.html` sidebar, all three tools)

- **Tokens** on `:root`: `--control-h` (32 px, topbar and empty state) and `--control-h-sm` (28 px, everything in the sidebar and viewbar), `--space-1..3`, `--fs-xs/sm/md`. In `body.extract .sidebar`, every button, input and select is `--control-h-sm` tall, so mixed rows line up. Don't add `.small` there.
- **Buttons**: default (bordered, white) for secondary actions such as Add ticks and Type a tick; `primary` (blue) always, not only as a next step, for Place grid corners / plot area, Place colorbar ends, Read labels with AI, Sweep, Run agent and Download CSV; `danger` (bordered, red) for Remove, Delete, Clear and Stop, always last in its row; `subtle` (borderless, with a hover background) for small utilities such as Overlay all and ×. Don't use `ghost` in the sidebar. No *Zoom to* buttons in the cards (the view has zoom).
- **Main step**: each card's main action is a `.btn.block` on its own row, spanning the card, as the card's first button: Place grid corners, Place colorbar ends, Measure scale bar, Draw profile, Run agent (after *API key and limits*, also a bordered `.btn.block`), Detect rows and columns, Read labels with AI, Sweep, Download profile CSV, and the heatmap's Download CSV (in ROI and Map, Download CSV shares a split row with Copy table / Long CSV).
- **Pairs**: two related buttons share a row in equal halves with `.card-actions.split` (Add ticks + Type a tick, Add x ticks + Add y ticks, Ellipse + Rectangle, Long CSV + Copy table; a third button such as Polygon takes half of the next row).
- **Icon-only buttons** (`.btn.icon-only`, with `title` and `aria-label`) sit at the top right of the card head in `.head-actions`: Panels add (+) and delete (trash); a trash button that removes the card's object in Grid / Plot area, Scale and Profiles (selected profile; hidden without one).
- **Status badge** sits right after the card title, not at the far right; head buttons and Results toggles take the right side (`margin-left: auto` in `extract.css`).
- **Empty visuals are hidden**: the colorbar strip shows only once there is a colorbar or a known colormap. Popups in the sidebar (the colormap picker list) must fit inside the card and never scroll the sidebar sideways.
- **Icons**: every sidebar button has `data-icon` (`place`, `plus`, `zoom`, `trash`, `download`, `copy`, `detect`, `type`, `ai`, `ruler`, `line`, `layers`, `play`, `pause`, `stop`, `reset`, `settings`), drawn by CSS masks in `base.css`, so JS may change `textContent` freely. Labels name the object: "Detect rows and columns", not "Detect".
- **Components**: build cards from `src/ui/` (`Btn`, `MainStep`, `IconBtn`, `CardHead`, `Fields`/`Field`, `SplitActions`, `Chip`, `Options`, `Hint`, `BoundInput`); they render the classes below, so new cards follow the standard by construction.
- **Key caps**: buttons with a hotkey show their first key as a cap (not with `noCap` / `data-no-cap`: zoom, Fit, page flips, Undo, Redo, whose keys are in the tooltip only); `Btn hotkey=…` sets `data-key` via `hotkeyTitle`, `updateTitles` does it for the static top and view bars; CSS draws it.
- **Toggles and modes**: `Btn pressed={…}` (static buttons: `ws.setPressed(el, on)`) sets `.active` and `aria-pressed` together.
- **Chips** (`.chip` in a `.chip-list`, with the name in `.chip-label`) are for selectable items: panels, regions, other pages. Selected = `aria-pressed="true"`. Never use `.btn` for list items.
- **Card anatomy**: `.card-head` (h2, optional `.tag`, status `.badge`, optional `.head-actions`), then the main step (`.btn.block`), then the fields, then `.card-actions` (secondary buttons, danger last), then `details.options` (summary, optional `.summary-note`, `.options-body`) for rarely changed settings. Settings needed on every run stay visible instead of in a disclosure (the Agent card's Model).
- **No instructional text** in the sidebar: no gray how-to sentences or "No X yet. Click …" hints. Put guidance in `title` tooltips or the *How it works* box. `.hint` is only for live status (results summary, agent status, measured scale) and `.notice` for problems.
- **Fields**: one per row, label on the left, control on the right (`.field` is a two-column grid in the sidebar); numbers short and right-aligned, selects and text inputs fill the right column. Group them in `.fields` (a column). A number and its unit share the control column in `.input-pair` (Length [1][cm]), with no separate Unit label. Select options use plain text (Log10, not Log₁₀). Textareas use `.field.stack` (label above). Never put a button on a field's row; it goes in `.card-actions`. Labels are short, with units in the label and explanations in `title`. Empty `.hint` and `.chip-list` elements collapse.
- Shared components go in the "UI standard" block of `base.css`; rules for one page go in its own sheet (`extract.css`, `colormaps.css`, `landing.css`).

## Browser testing tips (Claude's built-in browser)

- The Vite dev server reloads the page on save; after big changes check the code is live (e.g. `Colormeris.someFn.toString().includes(…)`, dev builds only). Check production behaviour on the `colormeris-build` preview (it rebuilds on start).
- When the Browser pane is hidden, `requestAnimationFrame` is paused, so pdf.js page rendering (`open_url` of a PDF, `go_to_page`) stalls. Start the call without awaiting it, then take a `screenshot` (which advances frames) and poll.
- Resizing with `resize_window` fires no `resize` event and no media-query `change`: dispatch `window.dispatchEvent(new Event('resize'))` yourself. Scroll events are not delivered while the pane is hidden either (they run in rendering steps), so after setting `scrollTop` dispatch `new Event('scroll')` on the scroller; a screenshot advances frames but also fires `resize`. The colormap viewer keeps the reader's place on resize (`createScrollAnchor` in `colormaps/scroll-anchor.ts`, wired by `app/use-scroll-anchor.ts`) from the anchor saved on scroll. Browse rows are built by an IntersectionObserver, which also needs frames: take a screenshot after scrolling or expanding sections.
- `javascript_tool` calls time out after 45 s. Start long agent runs with a click and poll in separate calls.
- Opening a file over an existing project calls `confirm()`; set `window.confirm = () => true` first.
- The agent can be exercised without cost by assigning a mock `globalThis.OpenRouterSDK = { OpenRouter: class { get chat() {…} get models() {…} } }` before pressing *Run agent*. The agent goes through `chat.send`; check `chatRequest.cacheControl` and `sessionId` there. A mock can return `usage: {promptTokensDetails: {cachedTokens}}`.
- Decision mode without LLM cost: a mock SDK whose first `chat.send` returns one `locate_heatmap` call per heatmap (and the second `set_ticks` / `finish`) runs the real Jev pipeline through the proxy for about $0.005 a page; read the `result` lines of `#agent-log` and the images in the captured `chatRequest.messages`. Tool results are JSON strings (`{"ok":true,"result":"Panel p3 \"Fig 2f\": …"}`).
- Offline harnesses must use the pixels the app sees: Chrome color-manages PNGs (Display P3 screenshots), so Python/PIL decodes of `test-images/test-*.png` differ (test-9's group strip was categorical in PIL pixels, binned in the browser's). Dump `getImageData` after `createImageBitmap` (as `pdf-loader.ts` does) instead.
- Synthetic test figure with known truth: draw a viridis grid on a canvas (e.g. cells from (237,143) to (887,663), colorbar at x 960–985, y 150–650, ticks 0/50/100), pass `canvas.toDataURL()` to `open_url`, and compare the agent's `set_grid` / `set_colorbar` against it.
